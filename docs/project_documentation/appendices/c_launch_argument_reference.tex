\chapter{Launch Argument Reference}
\label{app:launch}

This appendix documents the public and lower-level launch arguments used by the
supported simulation, visual-runtime, and task-execution profiles. Launch
values remain strings until launch or node conversion. Confirm the effective
arguments in an installed workspace with:

\begin{lstlisting}[language=bash]
ros2 launch <package> <file.launch.py> --show-args
\end{lstlisting}

\section{Composition Consistency Rules}

These rules apply to the public and optional launch surfaces in
Table~\ref{tab:launch-source-map}. Use that registry to locate each owning
include and argument declaration.

\begin{itemize}
  \item Floor bringup never includes visual inference or task execution.
  \item Assign one RGB bridge: if the supervisor launch owns it, visual runtime
        uses \code{enable_camera_bridge:=false}.
  \item If supervisor command/status topics change, update gateway parameters to
        the same names; high-level floor arguments do not expose that remap.
  \item Task execution currently requires floor
        \code{enable_room315_visual_obstacles=false} and gateway
        \code{external_obstacles_disabled=true}; the obstacle-enabled path is
        unsupported and fails closed.
  \item Visual \code{plansys2_update_enabled=true} needs separately available
        Problem Expert predicate services; task launch provides only planner.
  \item Multiple publishers on \rosname{/diagnostics} are intentional and share
        the same message type.
\end{itemize}
