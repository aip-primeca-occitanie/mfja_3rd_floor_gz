\chapteroverview
  {Maps each source change to the least expensive valid verification layers and

   registered, and runtime checks in increasing cost, then record exact commands,
   counts, environment, exclusions, and retained evidence.}

\section{Dependency and Static Checks}

From the workspace root:

\begin{lstlisting}[language=bash]
source /opt/ros/jazzy/setup.bash
source "$MFJA_WS/install/setup.bash"

rosdep check --from-paths \
  "$MFJA_REPO/mfja_3rd_floor_bringup" \
  "$MFJA_REPO/mfja_3rd_floor_description" \
  "$MFJA_REPO/mfja_rail_interfaces" \
  "$MFJA_REPO/mfja_robot_control_config" \
  --ignore-src --rosdistro jazzy \
  --skip-keys "python3-torch python3-torchvision"

git diff --check
python3 -m py_compile \
  "$MFJA_REPO"/mfja_robot_control_config/scripts/*.py \
  "$MFJA_REPO"/mfja_robot_control_config/launch/*.py \
  "$MFJA_REPO"/mfja_3rd_floor_bringup/launch/*.py

environment when running learned-runtime tests. A CMake cache created without

with \code{--cmake-clean-cache}.

\section{Focused Source Tests}

Start with the exact file related to a change:

\begin{lstlisting}[language=bash]
cd "$MFJA_REPO"
python3 -m pytest -q \
  mfja_robot_control_config/test/test_room315_rail_devices.py

python3 -m pytest -q \
  mfja_3rd_floor_description/test/test_room315_visual_observation_assets.py
\end{lstlisting}

Use an exact test node or \code{-k} expression while iterating. Some modules
perform module-level optional-dependency skips. Without Torch, a broad direct
invocation of the entire control test directory can terminate with pytest exit
code 5 (no tests collected) after collection behavior; that is not a pass.
Prefer explicit families/files and record counts.

\section{Registered Package Tests}

After a fresh build and overlay source:

\begin{lstlisting}[language=bash]
cd "$MFJA_WS"
colcon test --packages-select \
  mfja_3rd_floor_description \
  mfja_robot_control_config \
  --event-handlers console_cohesion+
colcon test-result --verbose
\end{lstlisting}

Do not report only the command's shell exit status. Capture passed, failed,
errored, skipped, and not-run counts, the configured optional dependencies, and
the Git commit. Remove/rebuild stale test metadata if a result unexpectedly
references a deleted test.

\section{Runtime Smoke Protocol}

Launch the base headless procedure from \cref{ch:operations}, wait at least five
seconds, then verify:

\begin{lstlisting}[language=bash]
ros2 topic echo --once /clock
ros2 service list | rg '^/world/room_315_only/(set_pose|create|remove)$'
ros2 topic echo --once \
  /room_315/rails/right/shuttles/state \
  mfja_rail_interfaces/msg/ShuttleState
ros2 topic echo --once \
  /room_315/rails/right/sensors/feedback \
  mfja_rail_interfaces/msg/SensorFeedback
ros2 topic info --verbose /mfja/conveyor/switch_states
\end{lstlisting}

Confirm the known-empty heartbeat when count is zero or the expected identity
when count is one. For motion tests, publish ON, observe MOVING/WAITING and
changing arc length, then publish OFF and require a newer DISABLED message.
Preserve logs for any pose-service or entity divergence.

\section{CI Gap and Recommended Baseline}

No checked-in continuous-integration workflow, \file{pyproject.toml},
\file{pytest.ini}, or lint configuration currently enforces the test surface.
The minimum future CI should contain:

\begin{enumerate}
  \item a clean Ubuntu 24.04/ROS Jazzy base dependency and four-package build;
  \item source tests including the nine unregistered files;
  \item ament tests with and without the optional Torch environment recorded;
  \item copied-install and installed-surface audits;
  \item headless Room 315 smoke with topic/service assertions;
  \item Repository Source Index and documentation validation with \code{make check}; and
  \item separately gated artifact-dependent V4 jobs that verify immutable
        bundle hashes before running.
\end{enumerate}

\noindent\textbf{Repository basis:} the repository root (absence of a checked-in
CI workflow and the named Python test configuration files), the four package
\file{CMakeLists.txt} files, and \file{docs/project_documentation/Makefile}.

\section{Test Result Record}

Every handover/release result should state:

\begin{itemize}
  \item commit, branch, date, supported OS/ROS/Gazebo, and workspace overlay;
  \item exact command and selected test files/packages;
  \item optional dependencies and external artifact identifiers/hashes;
  \item pass/fail/error/skip/uncollected counts and elapsed time;
  \item whether GUI/live Gazebo, copied install, and rollback were exercised;
  \item log/result locations and any known exclusions.
\end{itemize}

Never summarize ``tests pass'' when only a cached, selected, skipped, or
historical result exists.
