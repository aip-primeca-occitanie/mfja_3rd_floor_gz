Field-by-field message definitions are collected in \cref{app:interfaces}; the
purpose here is to state ownership, direction, and the checks that make a value
safe to consume.

\section{Gazebo--ROS Boundary}

The base bridge exposes ROS simulation time at \rosname{/clock} and three
world-scoped services under \rosname{/world/<world>/}: \code{set_pose},
\code{create}, and \code{remove}. The rail nodes call these services to move,
spawn, and delete visuals. Their logical state is internal Python state; Gazebo
does not compute rail topology.

Source files for this boundary are
\file{mfja_robot_control_config/launch/multi_robot_sim.launch.py},
\file{mfja_robot_control_config/scripts/room_315_kinematic_shuttle_node.py},
\file{mfja_3rd_floor_description/src/SmoothJointTrajectoryController.cc}, and

\subsection{Command-to-Effect Rule}

The command path is defined by
\file{mfja_rail_interfaces/msg/ShuttleCommand.msg},
\file{mfja_robot_control_config/scripts/room_315_kinematic_shuttle_node.py}, and
\file{mfja_robot_control_config/scripts/room_315_rail_safety_supervisor.py}:

\begin{enumerate}
  \item An operator or supervisor publishes a typed command.
  \item The side-specific rail node validates identity, legal state, occupancy,
        topology, and delayed device rules.
  \item Logical motion advances on simulation time and publishes fresh typed
        state and sensor feedback.
  \item The node converts logical rail position to a world pose and calls
        Gazebo \code{SetEntityPose}.
  \item The initiator verifies newer authoritative feedback; publication alone
        is never completion.
\end{enumerate}

\section{Switch Visual Synchronization}

This path is implemented by
\file{mfja_robot_control_config/scripts/room_315_kinematic_shuttle_node.py} and
\file{mfja_robot_control_config/scripts/conveyor_loop_mode_controller.py}.

The rail node schedules a typed actual switch change, publishes it, and mirrors
the accepted state as a comma-separated \code{selector=EXTERIOR/INTERIOR}
\code{std_msgs/msg/String} assignment list on
\rosname{/mfja/conveyor/switch_cmd}. The visual controller animates/configures
the Gazebo switch entity and publishes a latched assignment summary on
\rosname{/mfja/conveyor/switch_states}. Matching feedback acknowledges an
outstanding typed target; conflicting feedback is ignored until that target is
acknowledged. When no typed target is outstanding and
\code{sync_from_visual_switch_states=true}, an unmatched summary may schedule a
delayed update of the typed actual-state registry. Because routing reads that
registry, this synchronization path can affect topology; it is not merely a GUI
presentation update.

\section{Adding or Changing an Interface}

The interface build/install authority is \file{mfja_rail_interfaces/CMakeLists.txt};
runtime consumers are centered in
\file{mfja_robot_control_config/scripts/room_315_kinematic_shuttle_node.py},
\file{mfja_robot_control_config/scripts/room_315_rail_safety_supervisor.py}, and
\file{mfja_robot_control_config/scripts/room_315_task_execution_node.py}.

\begin{procedurebox}[Contract-change checklist]
\begin{enumerate}
  \item Decide whether the value is a public typed fact, simulation-only JSON,
        or internal implementation detail. Prefer a typed interface for stable
        cross-process contracts.
  \item Modify the owning \file{.msg}/\file{.srv} or versioned JSON schema;
        define units, legal values, empty/stale semantics, and authority.
  \item Update every publisher, subscriber, bridge, launch/config default,
        recorder/serializer, test fixture, and PDDL/visual adapter that consumes it.
  \item Rebuild \file{mfja_rail_interfaces} before dependent packages; source
        the new overlay in every terminal.
  \item Test valid, invalid, empty, stale, duplicate, delayed, and restart cases.
  \item Update this chapter, \cref{app:interfaces}, and the Repository Source
        Index.
\end{enumerate}
\end{procedurebox}
