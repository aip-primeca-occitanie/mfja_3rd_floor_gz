\section{Public rail interfaces}

The \code{mfja\_rail\_interfaces} package is independent of Gazebo-specific
controllers, allowing simulator nodes, tests and alternative actuation
providers to share public types.

\caption{Condensed rail-interface reference.}

\toprule

\midrule
\endfirsthead
\toprule
\textbf{Interface} & \textbf{Principal semantics}\\
\midrule
\endhead
\code{NamedState} & Canonical device name and symbolic state, embedded in

\tablerowrule

\tablerowrule

\tablerowrule
\small\path{VisualShuttleState} & Fused identity/presence validity, derived

\tablerowrule
{\footnotesize\path{VisualStateObservation}} & Image stamps, exact

\tablerowrule
\code{AddShuttle} service & Requested identity/start state and explicit
acceptance result\\
\tablerowrule
\makecell[l]{\code{JointTrajectory}\\\code{JointState}} & Namespaced robot joint command and
feedback; the operator helper validates profile, vector length and angular
unit conversion\\
\tablerowrule
\code{Twist}/odometry/TF & Independent TIAGo mobile-base command and feedback
surfaces for the full and base-only variants\\
\bottomrule
\end{longtable}

Three fields require careful interpretation. \code{ShuttleState.speed} stores a
speed setting rather than instantaneous velocity.
\code{reached\_target\_slot} indicates low-level setpoint completion; the full
task effect requires additional evidence. \code{VisualStateObservation.accepted}
indicates that the structural, freshness, presence and required-confidence
checks passed for the complete frame, while individual learned values remain
estimates. In this contract, \code{side} is derived from the fixed L/R identity prefix and
is not predicted. \code{segment\_confidence} uses Validation-only temperature
calibration; \code{loaded\_confidence} is an uncalibrated softmax decision value
and must not be interpreted as a probability guarantee. An absent identity has
no accepted visual facts.

\section{Runtime responsibility summary}

\begin{table}[H]
\centering
\caption{Responsibilities in the Room~315 task workflow.}
\label{tab:authority-matrix}
\begin{tabularx}{\textwidth}{@{}p{0.30\textwidth}X@{}}
\toprule
\textbf{Workflow decision} & \textbf{Responsible component}\\
\midrule
Interpret an English request & The local model proposes semantic fields;
explicit parsing, field fusion, domain validation and dialogue produce the
confirmed \code{TaskGoal}\\
\tablerowrule
Estimate visible shuttle state & The paired-camera model estimates public
segment, longitudinal location, box and payload state for identities supplied
by the configured presence registry; the fixed identity contract supplies rail
side\\
\tablerowrule
Select a visual input contract & The task runtime requires an exact visual
schema and checkpoint SHA-256 allowlist. An immutable authorisation manifest and
operator review can select a software profile, but do not themselves enable
planning or actuation\\
\tablerowrule
Create the symbolic plan & PlanSys2/POPF solves the current PDDL problem in a
separately command-authorised Gazebo profile. Selecting the visual contract
does not by itself grant planner mutation or actuation\\
\tablerowrule
Select the next operation & The project executive takes the first supported
plan step and observes the result before replanning\\
\tablerowrule
Translate the operation & The plan translator creates the sparse named command
for the addressed device or shuttle\\
\tablerowrule
Publish the command & The software supervisor checks the current state and
publishes the corresponding typed ROS~2 message\\
\tablerowrule
Apply and confirm the result & The kinematic controller applies the simulated
transition; the executive compares device and sensor reports with the expected
effect\\
\bottomrule
\end{tabularx}
\end{table}
