# Remaining claim boundaries

No unresolved item below is promoted to a completed result in the English
report.

| Boundary | Conservative treatment in the report |
|---|---|
| Statistical repeatability of the integrated workflow | The 12/12 campaign is an acceptance result for twelve predeclared, single-execution positive cases; it is not reported as a reliability estimate. |
| Live-graph fault injection | Fault and protective-boundary behaviour is supported by named automated tests. A separate preserved live fault campaign remains future validation work. |
| Dynamic robot operation in the all-robot profile | The retained smoke verifies launch composition, namespaced command/feedback interfaces and fresh state only; it makes no robot-motion, simultaneity or repeatability claim. |
| General language accuracy | The pinned ten-case corpus is reported only as an interface acceptance set. It does not establish open-vocabulary, multilingual, latency or reliability performance. |
| Visual generalisation | Locked-Test results apply to the generated Room 315 scene families, known shuttle identities and fixed simulated-camera geometry. |
| Dynamic and machinery-safety fidelity | Shuttle motion is kinematic and the software supervisor is a research safeguard in Gazebo, not a certified safety function. |
| Task-producer trust | The current execution subscriber assumes the official validated CLI and a trusted ROS graph; authenticated producer provenance remains future work. |

Names, dates, counts, metrics, source identities and hashes are reported only
when supported by the active evidence index or a cited primary source.
