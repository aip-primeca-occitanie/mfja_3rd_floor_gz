Quick Map: What VLA Means Here

Supervisor

Receives JSON on /room_315/vla/command, runs the safety decoder, then converts accepted event-level commands into switch, stopper, and shuttle commands.

action_vector safety decoder status JSON

Cameras

One independent overhead RGB-D camera per rail side. These images feed the recorder and the external VLA agent.

right_rail_rgbd left_rail_rgbd

Dataset / Benchmark

The recorder writes episodes and event-level labels. The benchmark runner dispatches task templates to generate demos and metrics.

This is the smallest useful VLA setup: Room 315, kinematic shuttles, the VLA camera bridge, and the VLA supervisor. Shuttles start stopped.

Send Commands to the VLA Supervisor

The model should output an event-level direct command: either a schema-v2 action_vector, or an equivalent primitive JSON command such as switches, stoppers, or shuttle. route_template remains useful for manual checks, demo generation, and benchmarks, but it is not the final model-output interface.

Visual Obstacles and Obstacle Scenarios

There is one independent visual obstacle marker for the right rail and one for the left rail. These markers are visible to the cameras but are not exposed in model_input as privileged state. The obstacle tool moves the marker in Gazebo and writes a pose cache used by m10 and m11 during the same simulation run.

To move objects with the mouse or see poses in Gazebo, use the full GUI: gui_config:=config/mfja_default.gui.config. The light GUI gui_config:=config/mfja_light.gui.config is better for recording performance, but it does not show the full move/rotate toolbar. Moving an obstacle only from the Gazebo GUI does not update ~/.ros/room315_vla_obstacles.json. Use the obstacle tool if m10/m11 should react to the new pose. At a fresh Gazebo startup, room_315_only.launch.py and full_floor.launch.py clear this cache by default because the world resets the obstacles to their default world-file poses.

Quick Troubleshooting

route_template rejected

Watch /room_315/vla/status. Usually no shuttle is on the required source slots. For example, right_yaskawa_to_staubli requires a shuttle on right slot 1 or 2.

No images

Check that enable_room315_vla:=true and the camera bridge are running. Try ros2 topic hz /room_315/vla/right_rail_rgbd/image.

Recorder is not recording

Check enable_room315_vla_dataset_recorder:=true. Start the teleop generator or publish episode_control manually.

Agent does not respond

Check the HTTP endpoint. If no model server exists, send a route_template directly to /room_315/vla/command for testing only. A real model should output an event-level command.

Do not use exact Gazebo pose as model input. The policy should learn from language + overhead_images + last_command only. Privileged state remains for evaluation and auditing.

import json
import sys
from pathlib import Path

path = Path(sys.argv[1])
for index, line in enumerate(path.read_text(encoding='utf-8').splitlines()[:5]):
    row = json.loads(line)
    print(f"event {index}")
    print("  task:", row.get("task"))
    print("  event_type:", row.get("event_type"))
    print("  model_input keys:", sorted((row.get("model_input") or {}).keys()))
    print("  action primitive:", (row.get("action") or {}).get("primitive"))
    print("  action_vector:", row.get("action_vector"))
    print("  image refs:", row.get("image_frame_refs"))

What the Recorder Writes

Path inside an episodeMeaningUse for training?
episode.json Episode summary: ID, task, frame count, event count, success/failure, and safety metrics. No. Use for inspection and bookkeeping.
events.jsonl Main training file. Each JSON line is a decision event: image/language/last_command before the decision, then action and action_vector. Yes. This is the important training file.
data.jsonl Framewise raw replay. It stores detailed frame state for audit and may repeat the same command over multiple frames. No. Do not use as supervised labels.
images/right_rail_rgb/*.jpg Right camera JPEG frames. Yes, through references in events.jsonl.
images/left_rail_rgb/*.jpg Left camera JPEG frames. Yes, through references in events.jsonl.

Important Fields in events.jsonl

FieldMeaning
model_input_schema_versionCurrently 3.
model_input.languageThe language goal or task text.
model_input.overhead_imagesReferences to camera images allowed for the model.
model_input.last_commandThe previous command; this is allowed model input.
actionReadable event-level symbolic command such as SET_SWITCHES or SHUTTLE_ON.
action_vectorThe same command encoded as a vector using action_space.yaml. This is the preferred model output.
privileged_evalExpert sensor/state data for evaluation and auditing only. Not model input.
observation.stateState vector for ablation/debug only. Do not use for the main visual policy input.
Bottom line: train on events.jsonl, and make the model output action_vector or direct primitive JSON. Do not train on data.jsonl, and do not use privileged_eval or observation.state as input for the main policy.
